# Native TLS worker phase 0 reference

This directory freezes the accepted Python/native behavior before any Rust runtime switch. `reference-manifest.json` records the baseline source hashes, accepted Sponsor and Concurro package manifest hashes, and every packaged worker, helper binary, and public circuit needed by the production path. The complete package manifests under `.artifacts/concurro-relay-native-v16/{sponsor,concurro}` cover the remaining bundled libraries and Python runtime.

## Run the comparison

From the relay repository root:

```sh
PY=.artifacts/concurro-relay-native-v16/sponsor/native-runtime/python
"../$PY" native/port-reference/check.py
"../$PY" -B -m unittest discover -s native -p test_ingress_cancellation.py
cargo nextest run --manifest-path native/port-reference/probe/Cargo.toml --offline --locked
```

The package path above is relative to the parent `concurro` workspace, so `../$PY` resolves it from this repository. The Python check imports the current production reference and compares nine semantic/wire groups with `vectors.json`; it makes no provider or native-helper call. The Rust probe checks fixture CA and hostname rejection plus both HPACK decoders against the same indexed/Huffman bytes. `--freeze` rewrites the vectors and is reserved for an explicitly reviewed baseline update.

Phase 2 adds `tls13-fixture.json`, generated by `generate-tls13.py` with the accepted packaged Python and its production TLS modules. It contains fixture-only CA certificates, both ALPN profiles' exact hello and authenticated record bytes, negative ALPN/Finished records, and post-handshake KeyUpdate bytes. Regeneration uses fresh fixture keys and rewrites the frozen bytes; review the new fixture before accepting a replacement. Run `cargo nextest run -p concurro-relay-tls13 --offline --locked` to compare the Rust library against it.

`reference-manifest.json` records both current source hashes and the accepted v16 source snapshot hashes. The current `tls13_product_native.py` differs from the accepted snapshot only in trailing blank lines. The current dev gateway includes a later unknown-thread-parent response fix, so its source hash differs from v16; the accepted package binary is identified separately.

## Production import boundary

`role.py` imports `Tunnel`, then `ingress.Adapter`, `candidate_a.bootstrap`, and `tls13_product_http_h2`'s role loops, control codec, prefix generator and request-head builder. The latter imports `tls13_product_native`, both `tls13_joint` profiles, and `candidate_a`'s indexed request, response, and audit classes. `ingress` imports the same control codec. The package's `hpack.Decoder` is used only for Claude response headers; `cryptography` supplies TLS records, X.509 and signatures. The worker entry point is `role.py`, not the large product file's `main`, `harness`, benchmark, login, or standalone request-file branches. `CONCURRO_PROVIDER_PROTOCOL` is read only by the standalone request-file branch.

The Rust launch bridge in `crates/protocol/src/native.rs` already owns child lifecycle, control and auxiliary Unix sockets, credential stdin, readiness and audit stdout, and process-group cleanup. Its launch behavior should move into `crates/native` in phase 1. Existing `crates/protocol/src/ws.rs` and `crates/dev/src/gateway.rs` contain reusable WebSocket parsing and Hyper upgrade patterns; their TLSNotary proof assumptions do not transfer.

## Helper contracts

| Helper | Input and readiness | Success contract |
| ---- | ---- | ---- |
| `HandoffKeyShare` | No args; writes exactly 69 offer bytes on stdout; stdin receives peer 69-byte offer, then `00 17 00 41` plus 65-byte provider point. | Next stdout reads are 65-byte joint point and 64-byte private contribution; after stdin closes, exit 0 within five seconds. |
| `mascot-party.x` | `-N 2 -I -P <P256 prime> -S 128 -pn <port> -h <host> -p <0 or 1> [-mp <own port>] concurro_ectf_field`; stdin is two decimal coordinates and newlines. Sponsor publishes mapped coordination port first; certificates in `Player-Data`. | Exit 0, stdout contains line `valid 1` and `share <signed decimal>`; stderr saved as metrics; deadline at least 120 seconds. |
| `HandoffPartyKrrw` | Party 1: `<1> <circuit>`; party 2: `<2> <circuit> <mapped port>`; private bytes on stdin. Party 1 emits `HANDOFF_READY <port>` on stderr within 90 seconds, then port travels through the authenticated control channel. Both children receive session-binding digest in env. | Exit 0; stdout starts with byte `01`; peers exchange SHA-256 of full public stdout and reject disagreement. Completion deadline at least 180 seconds Sponsor, 120 seconds Concurro. |
| `HandoffPrefix` | `generate <partial-head length> <credential offset> <credential length> <output.tmp>` under an exclusive cache lock. | Exit 0 and generated public circuit file atomically renamed into cache; no stdout readiness marker. Deadline at least 240 seconds. |
| `handoff-request-proof` | Sponsor: `verifier`, JSON claim on stdin; Concurro: `prover <local proxy port>`, same claim form. Sponsor stderr emits `REQUEST_READY <port>` within 30 seconds; role-specific proxy connection carries proof bytes. | Exit 0 and stderr includes `REQUEST_OK`; Sponsor proof deadline at least 90 seconds; proxy joins within five seconds. |
| `openssl` | `req -x509 -newkey rsa:2048 ... -days 1 -subj /CN=P0|P1 -addext subjectAltName=DNS:P0|P1`, then `rehash <Player-Data>`; no stdin. | Exit 0; each role validates peer certificate CN before MASCOT. |

Worker control frames have a four-byte big-endian JSON length capped at 1,000,000, with base64 `data`; tunnel frames use one opcode byte, four-byte channel, four-byte length capped at 65,536. Concurro readiness is a stdout line `NATIVE_READY <host>:<port>`. Audit and cancellation lines are `NATIVE_AUDIT <JSON>` and `NATIVE_CANCEL <reason>`; the bridge consumes those exact prefixes.

## Dependency and build decisions

The standalone probe compiled against locked `rustls 0.23.46`, `rustls-webpki 0.103.17`, `ring 0.17.14`, and `rcgen 0.13.2`. `WebPkiServerVerifier` works for configured CA chain and hostname checks without a second X.509 implementation. TLS CertificateVerify still needs the supported scheme and transcript binding check in phase 2.

The production Python HPACK decoder passed dynamic-index, state retention, and Huffman vectors. The first unprivileged Cargo fetch for Rust `hpack 0.3.0` failed with registry-proxy HTTP 403; a scoped fetch succeeded. Its executable check showed correct state and Huffman behavior, but also that `set_max_table_size(0)` does **not** reject a subsequent encoded 4096-byte size update. Reject it as a direct response decoder. The bounded `httlib-hpack 0.1.3` decoder passed the same vectors, malformed-index rejection, and excessive-size-update rejection. Select `httlib-hpack` for phase 5, subject to the usual complete HEADERS/CONTINUATION assembly and a caller-owned decoded header-list size bound; the dependency is confined to this test probe for now. Neither decoder is the deterministic request encoder, which must keep authorization at dynamic index 62.

The proposed crate graph is `native -> {tls13, native-transport, provider-protocol, protocol}`; leaf libraries do not depend on `native`, and `protocol` does not depend on `native`. The isolated probe is outside the workspace and selects no runtime. Production Rust modules stay unchanged in phase 0.

The accepted package is not hermetic from this checkout. `native/package.py` requires the separate runnable MVP source/build root with DiStefano, MP-SPDZ, request-proof, Python dependencies, OpenSSL, and macOS arm64 libraries. The external build recipe is `concurro/.worktrees/sponsor-relay-design/docs/proposals/sponsor-relay/tls13-runnable-mvp/README.md`; its pinned upstream revisions are copied into `reference-manifest.json`. A clean checkout must build that external root using the pinned recipe and verify its outputs against the accepted manifest, or supply the accepted `.artifacts/concurro-relay-native-v16` bundle explicitly. The package and its source tree are local evidence, not repository build inputs.
