# Packaged native TLS 1.3 backend

Both role packages launch the bundled Rust worker by default.
`CONCURRO_NATIVE_RUST_WORKER` selects a development worker binary explicitly.
The worker handles Codex WebSocket continuations and successive Claude HTTP/2
requests over one protected session. Frozen TLS and control-wire test inputs are
in `native/fixtures`; the Python worker used during the port is retained in Git
history at `aa8c3d0`.

Claude Message Threads use compact continuations by default. Set
`CONCURRO_CLAUDE_MESSAGE_THREADS=0` on Concurro for full-context diagnostics.
The hosted fixture also accepts `--claude-full-context`.

## Building the native runtime

The helpers are built from pinned upstream commits plus Concurro's changes, which are
checked in: [`sources/`](sources) holds the DiStefano, MP-SPDZ and request-proof
additions and patches, [`patches/`](patches) the Codex KRRW and mpz2 base-seed patches.
`prepare_sources.sh` fetches DiStefano, MP-SPDZ and libOTe at their recorded commits and
applies them. The public handshake circuit is generated by the built `HandoffDeriveShares`
(`generate_circuit.sh`), which checks it against the accepted SHA-256
`6abe1747161ca22474ee1430920d667c7e55b308823028309a24c5453c56dc0d`. Run
`../scripts/upstream.sh` first; each recipe takes a build directory which must not exist.

| Recipe | Platform | Result |
| ---- | ---- | ---- |
| `build_macos_arm64.sh BUILD_DIR` | macOS arm64 with Homebrew `cmake boost gmp libsodium openssl` and Go | Helper runtime for `package.py` |
| `build_linux_amd64.sh BUILD_DIR` | Docker with Linux amd64 | `BUILD_DIR/package-concurro-v3`, the hosted verifier package ([details](linux-amd64-build.md)), and the Sponsor and Concurro packages in `BUILD_DIR/packages/` |

`package.py` assembles separate Sponsor and Concurro bundles from that runtime and three
Rust binaries, for macOS arm64 or, in the Linux builder, Linux x86-64. OpenSSL, its
configuration, dynamic libraries, and public circuits are included.

- **macOS:** the packager copies the full non-system Mach-O dependency closure, rewrites
  loads and library identities to package-local paths, removes rpaths, signs the images ad
  hoc, and audits the result.
- **Linux:** it copies every ELF dependency except glibc's own libraries into
  `native-runtime/lib`, gives each image a `$ORIGIN`-relative runpath, and audits that every
  image loads only packaged libraries or glibc. It records the newest glibc version the
  package requires (non-weak symbol versions) in `manifest.json`.

On both platforms, `notices.py` writes `licenses/`: notices and provenance for the copied
system libraries (Debian or Homebrew metadata), the helpers' upstream checkouts and the
crates in the Rust binaries. With `--sources DIR`, the packager downloads the exact sources
of the shipped copyleft libraries. Homebrew, the compiler, Python, and the
source checkout are build inputs only. Each package has a SHA-256 manifest. Private
MASCOT transport keys and OT preprocessing are generated for each session outside the
bundle.

```bash
native/build_macos_arm64.sh "$NATIVE"
RUSTC_WRAPPER= cargo build --release -p concurro-relay -p concurro-relay-dev -p concurro-relay-native --bins --locked
python3 native/package.py --role sponsor --runtime "$NATIVE" --openssl "$(brew --prefix openssl)/bin/openssl" --relay target/release/concurro-relay --verifier target/release/dev-verifier --worker target/release/concurro-native-worker --output "$PACKAGES/sponsor"
python3 native/package.py --role concurro --runtime "$NATIVE" --openssl "$(brew --prefix openssl)/bin/openssl" --relay target/release/concurro-relay --verifier target/release/dev-verifier --worker target/release/concurro-native-worker --output "$PACKAGES/concurro"
python3 -B -m unittest native.test_package -v
```

[`build-sponsor.yml`](../.github/workflows/build-sponsor.yml), dist's build job for releases
([docs/releasing.md](../docs/releasing.md)), runs these steps, archives the Sponsor package
with `release.py` under the name dist planned, installs and tests the archive. `release.py`
refuses a package containing the build directory or home path, and records the archive's
checksum for dist. Set
`CONCURRO_NATIVE_OUTPUT` to keep session logs and fresh private state in a
chosen directory. Generated prefix circuits are cached in its `public-circuits`
directory, or without it in `concurro-relay/public-circuits` under the user's cache
directory. The cache directory must belong to the user and not be writable by others.

Start `dev-verifier` from the Concurro package with the desired `--route`
(TLS 1.3 is the default), then run the registered Sponsor package's
`concurro-relay run`.
Repeat `--route` to assign different routes to successive link slots. With one
route flag, all slots use that route. Each `NATIVE_SESSION_READY` line prints a
dedicated `ingress` for its `relay` and `link` slot; point each concurrent CLI
task at its own ingress. The shared `--listen` address remains a single-link
compatibility alias pinned to the first ready authenticated link. For an
offline provider, pass `--provider-host`, `--provider-port`, and
`--provider-ca` to `dev-verifier`, and set `CONCURRO_NATIVE_PROVIDER_CA` to the
same CA on Sponsor. The live default uses the route's provider host on port
443 and the system CA file.

Concurro keeps the H2 ingress open for successive Claude requests in one
session. Authenticated Claude response headers and DATA are forwarded to the
local CLI as chunked SSE while the provider stream is still open. Each proved
request and its Concurro-reported usage appear in the
Sponsor activity stream. Set `CONCURRO_NATIVE_AUDIT_TEXT=1` on Sponsor to print
the full proved request body and retain it in the session audit file; the
default session file stores only its digest. Keep the audit output local if
prompt text is sensitive.

Closing the local Claude connection during bootstrap or response forwarding,
or sending Codex `response.cancel` during a turn, ends that native session.
The verifier accepts a new registered link for the next request. SIGINT and
SIGTERM stop isolated native worker process groups and remove bridge sockets.

The ignored bootstrap integration tests use `python3` for a loopback TLS provider and
`openssl` for fixture certificates. They need sibling `sponsor` and `concurro` packages
built as above:

```bash
CONCURRO_PHASE3_FIXTURE_BUNDLE="$PACKAGES/sponsor/native-runtime" \
  cargo nextest run -p concurro-relay-native --test bootstrap --run-ignored all --locked
```

The same tests include `packaged_request_proof`: the two packages' request-proof helpers
prove and verify two successive records through the authenticated tunnel. For Linux,
`test_linux_amd64.sh` runs these tests on an installed archive in a clean container
([details](linux-amd64-build.md)).

`fixture_server.py` supports local offline CLI fixtures when the external
provider fixture source and certificates are supplied. Historical phase and
benchmark runners are available at the commits in [ARCHIVE.md](../ARCHIVE.md);
they are not part of the current package build.
For a single Codex CLI invocation with one tool iteration, use
`--route codex --tool-loop --calls 3` and set
`CONCURRO_NATIVE_TEST_TURNS=2` on Concurro. The preflight with
`generate:false` is counted separately from the two generated turns.
`CONCURRO_NATIVE_TEST_TURNS` bounds fixture runs only; omit it for a persistent
Claude ingress.

For an offline TLSNotary fixture, `fixture_provider` (built with
`cargo build --release -p concurro-relay-dev --example fixture_provider`) serves
the existing TLS 1.2 mock provider using `CONCURRO_FIXTURE_TOKEN`. Pass its
printed socket to `dev-verifier --backend tlsnotary --fixture-provider`, and
set `CONCURRO_TLSNOTARY_FIXTURE=1` for the Sponsor relay. These explicit
fixture settings select the mock certificate host and CA; without them,
TLSNotary uses the route host and Mozilla roots.
